    先明确这次要学会什么

    本篇整合原始课时「提示词工程 / 结构化 Prompt 框架」，目标不是背公式，而是建立一套可迁移的提示词组织能力。

    01 · Mental Model

    什么是结构化 Prompt 框架

    在上一篇《如何设计 Prompt》中，我们介绍过用标题、分节组织提示词的写法。业界在此基础上沉淀出一批标准的通用框架。

    与其说它们是“框架”，更准确地说，它们是一组 Prompt Templates：用来规范你向大模型发出的请求，让模型更好地理解你的意图、背景、角色与格式要求。

    六种框架一览

    框架全称要素数量一句话定位
    RTFRole–Task–Format3最基础的模板，简洁高效
    ICIOInstruction–Context–Input–Output4指令与输入数据分离，适合处理具体数据
    CRISPECapacity–Role–Insight–Statement–Personality–Experiment6人格化与可控化，鼓励探索性输出
    CO-STARContext–Objective–Style–Tone–Audience–Response6面向受众的结构化输出，可控性高
    TIDD-ECTask Type–Instructions–Do–Don't–Example–Content6明确允许与禁止行为，输出精准可靠
    BROKEBackground–Role–Objective–Key Result–Evolution5目标导向、结果可评估、支持持续迭代
    RTF 02 · Foundation

    RTF：最小可用结构

    RTF 是最基础的提示词模板，强调角色设定、任务说明与输出格式。它简洁高效，适合通用类任务或简单任务。

    Role 角色
    定义模型的身份或专业背景。
    Task 任务
    说明模型要完成的具体目标。
    Format 格式
    指定输出的格式、风格或语气。
    查看 RTF 完整示例
    TEXT · RTF
    # Role
你是一名资深市场分析师。

# Task
请分析当前中国新能源汽车市场的发展趋势，指出未来三年的主要增长点。

# Format
请以 Markdown 表格形式输出，包含“趋势”、“原因”、“预测增长率”三列。
    ICIO 03 · Separation

    ICIO：把指令与输入分开

    ICIO 通过清晰分隔任务指令、背景信息、输入与输出要求，让模型在复杂场景中仍能高效执行。它适合需要上下文理解或多阶段推理的任务。

    Instruction 指令
    核心任务说明。
    Context 上下文
    背景与辅助信息。
    Input 输入
    具体需要处理的文本或数据。
    Output 输出
    结果格式或表达要求。
    查看 ICIO 营销文案示例
    TEXT · ICIO
    # Instruction
请为指定产品生成一段简短、有吸引力的营销文案。

# Context
你是一名资深品牌营销文案策划，擅长为电商产品撰写高转化率的广告语。
目标受众是年轻、注重品质的都市白领。

# Input
产品名称：AI健康监测手环
产品特点：实时监测、可测量血压血氧、监测睡眠和呼吸暂停、
外观时尚简约、佩戴轻盈舒适

# Output
请输出一段不超过100字的营销文案，请使用markdown格式，
语言简洁、有节奏感，突出健康的生活方式。
    工程师视角 Instruction 相当于方法体逻辑，Input 相当于方法入参。指令与数据分离后，同一段指令可以复用于不同输入，这正是后续提示词模板，例如 Spring AI PromptTemplate 的工作方式。
    CRISPE 04 · Creativity

    CRISPE：人格化与探索性

    CRISPE 通过能力、角色、洞察、任务、个性及实验性控制，让生成内容更具创造性与一致性，常用于学术、科研、内容创作等领域。

    Capacity 能力
    确定智能体的能力边界。
    Role 角色
    明确身份定位。
    Insight 洞察
    提供必要的知识视角或上下文背景。
    Statement 声明
    定义具体的任务目标，也就是 Task。
    Personality 个性
    设置个性化的语气与风格。
    Experiment 实验
    指定探索性要求，例如提出假设或生成多个答案。
    查看 CRISPE 市场策略示例
    TEXT · CRISPE
    # Capacity and Role（能力与角色）
你是一名资深市场策略分析师，擅长品牌定位与消费趋势洞察，
熟悉零售行业的数据分析与竞争对比方法。

# Insight（洞察）
某科技品牌计划在明年推出一款主打AI功能的智能手表，
目标群体为25-40岁的城市白领。
公司希望通过差异化策略抢占高端可穿戴设备市场。

# Statement（声明）
请撰写一份市场策略分析报告，包含以下内容：
1. 当前智能手表市场格局与主要竞争者分析
2. 目标用户画像与购买动机
3. 产品差异化与品牌定位建议
4. 三条可执行的市场推广策略

# Personality（个性）
请以专业咨询顾问的语气撰写，逻辑清晰、数据导向。
报告语言应简洁有力，避免空泛表达。

# Experiment（实验）
在报告结尾，请额外提供一个“创新性市场假设”，
例如：基于AI健康数据洞察的“主动健康推荐”功能，
并简要说明这一创新可能带来的商业价值与潜在风险。
    注意 Capacity 与 Role 常合并成一段来写，二者共同回答“模型是谁、擅长什么”这个问题。
    CO-STAR 05 · Control

    CO-STAR：围绕受众精确表达

    CO-STAR 通过明确任务要素，帮助用户更精准地传递需求。任务越复杂、输出越结构化、可控性要求越高，它的效果越明显。

    Context 背景
    提供场景、前提或背景，让模型理解“为什么做”。
    Objective 目标
    明确希望达成的结果，帮助模型聚焦“做什么”。
    Style / Scope 风格 / 范围
    约束表达风格，或界定任务的内容边界。
    Tone 语气
    指定正式、幽默、专业或轻松等表达语气。
    Audience 受众
    说明目标读者，帮助模型选择合适术语与表达。
    Response 响应形式
    要求列表、短文、步骤或表格等输出结构。
    Style（风格）约束写作方式，例如叙事化、数据驱动、简洁直接。它关注内容“如何表达”。
    Scope（范围）界定内容涵盖范围与限制条件。它关注内容“讲到哪里为止”。两种解释都在给输出加约束，按需选择即可，不必纠结名称。
    查看 CO-STAR 青少年教育示例
    TEXT · CO-STAR
    # Context（背景）
近年来青少年沉迷社交媒体、遭遇网络不良信息的问题频发，
学校计划开展相关主题教育活动；

# Objective（目标）
帮助青少年理解合理使用社交媒体的重要性，并提供可操作的建议；

# Scope（范围）
聚焦 13-17 岁青少年，涵盖使用时长管理、信息辨别、隐私保护
3 个核心方面，避免过于学术化的理论；

# Tone（语气）
亲切、鼓励，像学长学姐的建议，避免说教；

# Audience（受众）
初中至高中阶段的学生；

# Response（响应形式）
分点列出 5 条具体建议，每条配一个简短案例或比喻。
    TIDD-EC 06 · Guardrails

    TIDD-EC：明确能做与不能做

    TIDD-EC 明确任务目标、执行指令、允许与禁止行为，并提供示例和背景信息。它适用于教育培训、法律咨询、技术支持等强规范场景。

    Task Type 任务类型
    明确任务的性质和目标。
    Instructions 指令
    提供执行任务的具体步骤或指导。
    Do 应做
    列出应当执行的操作或行为。
    Don't 不应做
    指出应避免的错误或不当行为。
    Example 示例
    提供期望输出的示例，帮助模型理解结果。
    Content 用户内容
    用户提供的背景信息或数据。
    查看 TIDD-EC 法律意见书示例
    TEXT · TIDD-EC
    # 任务
撰写法律意见书

# 指令
根据客户提供的案件信息，分析法律风险并提出可行建议

# 你应该做
- 结合相关法律法规进行分析
- 条理清晰地列出风险点
- 提供操作性建议

# 你禁止做
- 不要提供具体的法律诉讼策略或个案判决
- 避免主观推测，确保内容专业客观

# 示例
客户希望了解合同条款中的潜在风险，分析指出关键条款可能存在的
履约争议，并给出建议如完善合同条款或加强证据准备

# 用户内容
- 案件类型：商业合同纠纷
- 关键条款：付款条款、违约责任、交付时间
    独特价值 在法律、医疗、金融客服等合规敏感业务中，明确写出禁止行为，往往比只写正向要求更能压住模型的“自由发挥”。这也是生产环境系统提示词中最常见的写法之一。
    BROKE 07 · Outcomes

    BROKE：让结果可验收、可迭代

    BROKE 通过上下文、身份、任务目标、衡量标准及改进方向，引导模型生成更贴合目标、可评估和可迭代的输出。

    Background 背景
    描述任务上下文，提供必要理解依据。
    Role 角色
    明确模型应扮演的身份，引导输出风格与深度。
    Objective 目标
    定义任务的具体目标或预期结果。
    Key Result 关键结果
    设定衡量成功的标准或指标，确保输出可评估。
    Evolution 进化
    提供改进建议或后续步骤，支持持续优化。
    查看 BROKE 校园活动示例
    TEXT · BROKE
    # 背景（Background）
学校希望提高学生的环保意识，计划开展一次以校园环保为主题的活动。

# 角色（Role）
作为校园活动策划师，负责设计活动方案并确保可执行性。

# 目标（Objective）
通过活动让学生了解环保知识并积极参与实践。

# 关键结果（Key Result）
活动结束后，学生参与率达到80%以上，
提交的环保创意作品数量不少于50份。

# 进化（Evolution）
根据活动反馈调整宣传策略和活动形式，优化互动环节，
使下一次活动更具吸引力。
    与 OKR 的联系 BROKE 明显借鉴了管理学中的 OKR 思想：Objective 定方向，Key Result 定可量化的验收标准，Evolution 对应复盘迭代。需要模型输出“可验收、可优化”时，它最合适。
    08 · Decision Guide

    框架对比与选型

    先识别任务最突出的特征，再选择框架。任务没有唯一答案，必要时可以组合使用。

    框架核心特色典型适用场景复杂度
    RTF三要素极简结构通用任务、简单任务低
    ICIO指令与输入数据分离需要上下文理解或多阶段推理、有具体待处理数据中
    CRISPE人格化、支持探索性输出学术、科研、内容创作中高
    CO-STAR强调受众与响应形式，可控性高企业报告、课程设计、市场策略分析中高
    TIDD-EC明确应做与禁止做教育培训、法律咨询、技术支持等强规范场景中高
    BROKE关键结果可评估、支持迭代活动策划、产品设计、需要持续改进的任务中高

    09 · First Principles

    万变不离其宗：四大核心要素

    不必过于拘泥于框架名称。归根结底，最重要的是明确角色定位、任务目标、上下文背景与输出格式。

    CORE 01

    角色定位

    回答“模型是谁”。对应 RTF 的 Role、CRISPE 的 Capacity 与 Role、BROKE 的 Role，ICIO 中常写入 Context。

    CORE 02

    任务目标

    回答“要做什么”。对应 Task、Instruction、Statement、Objective 等要素。

    CORE 03

    上下文背景

    回答“为什么做、依据什么”。对应 Context、Input、Insight、Content 与 Background。

    CORE 04

    输出格式

    回答“怎么呈现”。对应 Format、Output、Personality、Tone、Response 与 Example。

    核心要素回答的问题在各框架中的体现
    角色定位模型是谁RTF 的 Role、CRISPE 的 Capacity 与 Role、BROKE 的 Role、ICIO 常写入 Context
    任务目标要做什么RTF 的 Task、ICIO 的 Instruction、CRISPE 的 Statement、CO-STAR 的 Objective、TIDD-EC 的 Task Type 与 Instructions、BROKE 的 Objective
    上下文背景为什么做、依据什么ICIO 的 Context 与 Input、CRISPE 的 Insight、CO-STAR 的 Context、TIDD-EC 的 Content、BROKE 的 Background
    输出格式怎么呈现RTF 的 Format、ICIO 的 Output、CRISPE 的 Personality、CO-STAR 的 Tone 与 Response、TIDD-EC 的 Example

    把大模型当人看

    是人就会犯错，模型也可能不按要求输出。没有达到理想效果时，不要着急，要针对性地指导它：合理调整提示词与格式，保持结构清晰具体，给出明确任务指令；同时避免信息过载，不让模型被过多细节干扰。

    10 · Engineering

    工程实践：在 Java 中使用结构化提示词

    工程落地时，结构化提示词通常固化为系统提示词，用户的具体问题作为用户消息传入。这正好对应 ICIO 中“指令与输入分离”的思想。

    JAVA · SPRING AI CHATCLIENT
    ChatClient chatClient = ChatClient.builder(chatModel).build();

String answer = chatClient.prompt()
        .system("""
                # Role
                你是一名资深市场分析师。

                # Format
                请以 Markdown 表格形式输出，包含“趋势”、“原因”、“预测增长率”三列。
                """)
        .user("请分析当前中国新能源汽车市场的发展趋势，指出未来三年的主要增长点。")
        .call()
        .content();

    其中，RTF 的 Role 与 Format 放进系统提示词，作为稳定不变的“模板”；Task 由用户消息动态传入。后续学习提示词模板管理时，还可以把模板中的可变部分抽成占位符参数。

    11 · Summary

    把框架变成能力，而不是负担

    1. 结构化 Prompt 框架本质上是一批提示词模板，用于规范向大模型传递意图、背景、角色与格式要求的方式。
    2. 六种框架各有侧重：RTF 极简通用；ICIO 分离指令与输入；CRISPE 人格化且鼓励探索；CO-STAR 强调受众与响应形式；TIDD-EC 明确允许与禁止行为；BROKE 以关键结果驱动可评估、可迭代的输出。
    3. 所有框架万变不离其宗，核心是四大要素：角色定位、任务目标、上下文背景、输出格式。
    4. 不要拘泥于框架名称。保持结构清晰、指令明确、避免信息过载，输出不理想时通过迭代调整提示词来指导模型。

    先在心里作答，再点击查看参考答案。

    ICIO。它显式分离 Instruction 与 Input，稳定指令可以复用，输入数据按次替换。

    TIDD-EC。它通过 Do 与 Don't 明确允许和禁止行为，适合强规范、合规敏感场景。

    角色定位、任务目标、上下文背景、输出格式。这四项是所有结构化 Prompt 框架的共同底层逻辑。
